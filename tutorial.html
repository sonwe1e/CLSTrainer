Production-oriented two-frame classification

把两张连续画面，训练成可信的分类决策

CLSTrainer 是一个面向多游戏、双帧二分类任务的训练框架。它把数据审计、 懒采样、单卡/八卡训练、部署精度评估、错例报告与精确恢复组合成一条可验证的生产链路。

开始使用 → 查看技术架构
2 × RGB每个样本由两张连续画面组成
448 × 208单帧 tensor 为 [3, 208, 448]
[B, 2]模型输出二分类 logits
p₁ > 0.99固定业务分数判定规则
01 / PURPOSE

项目要解决什么

目标并非只让模型“跑起来”，而是让百万帧数据、严格阈值、多游戏公平性和 NPU 分布式训练在同一套可审计契约下工作。

01

捕捉时间变化

单张画面可能缺少动作上下文。框架同时输入 image0 与 image1，让模型学习两帧之间的变化，而不仅是静态纹理。

08

扩展到多卡训练

同一套入口支持 CPU/CUDA 调试、Ascend 单卡和 HCCL 八卡训练，并保留每个 rank 的随机状态以实现精确恢复。

99

让指标可以解释

除全局 F1 外，同时观察 macro-game、worst-game、校准指标和按视频错例，避免大游戏掩盖小游戏退化。

02 / ARCHITECTURE

从文件到决策的技术架构

整体采用“离线索引 + 在线懒采样 + 设备端训练 + 分布式流式评估”的分层设计， 将大规模数据的内存压力和评估报告的 I/O 压力拆开处理。

04 / QUICK START

从零到第一次训练

以下命令按推荐执行顺序排列。NPU 环境必须先安装与服务器 CANN 版本匹配的 PyTorch 和 TorchNPU，项目本身不会替换它们。

01

安装项目

基础安装用于 Ascend；开发机可安装 CUDA 或 dev 额外依赖。

shell

python tools/audit_dataset.py \
  --config configs/npu_production.yaml \
  --index-dir indexes \
  --output-dir reports/data_audit \

05 / EVALUATION

评估、选模与错例

quick 用于训练过程中的轻量观察，full 用于完整指标和 best 选择。 同一步同时满足两者时只运行 full。

QUICK TEST

快速反馈

每视频时间均匀抽取固定数量的 delta=2 pair，只写 metrics 与有限 FP/FN、临界样本 Parquet。

FULL TEST

完整评估

枚举全部合法 pair，使用直方图分布式 AUC、整数分组聚合和缓冲 Parquet 写入。

FINAL FULL

最终比较

训练结束的 full 同样参与组合分数比较，可更新 best checkpoint，不会遗漏最后一步模型。

组合选模

selection config
evaluation:
  selection_metric: composite
  selection_weights:
    global_f1: 0.40
    macro_game_f1: 0.40
    worst_game_f1: 0.20
  minimum_worst_game_f1: null

首轮可靠基线完成后再设置非零 worst-game 下限，不要凭空猜测门限。

报告如何解释

  • 正类 game-label：重点看 recall 与 FN rate
  • 负类 game-label：重点看 specificity 与 FP rate
  • Brier、ECE：观察分数校准稳定性
  • observed_dev_test：说明该集合参与了选模
◆
部署精度一致性
生产评估使用 evaluation.amp=true 与 bfloat16，模型选择依据与部署一致的低精度前向，而不是固定 FP32。
06 / ARTIFACTS

训练结束后会得到什么

权重、恢复状态和报告相互独立。部署端无需理解 optimizer 或 sampler， 训练恢复也不会依赖一个缺少随机状态的“纯权重”文件。

产物用途关键契约
model_last.pth部署或独立推理纯 state_dict，可直接 load_state_dict
model_last.metadata.json追踪权重来源记录 global_step、epoch 与角色
checkpoint_last.pth精确恢复训练模型、optimizer、scheduler、scaler、sampler 与各 rank RNG
metrics.json全局指标F1@0.99、AUC、Brier、ECE、置信度分布
metrics_by_*.csv分组诊断game、game-label 与 video 维度
false_*.parquet完整错例集合流式写入，不在 rank 0 集中保存 Python 列表
errors.html人工复核packed 模式自动引用有限的 previews/*.png
纯权重加载
import torch

state_dict = torch.load(
    "runs/your_run/checkpoints/model_last.pth",
    map_location="cpu",
    weights_only=True,
)
model.load_state_dict(state_dict)

08 / FAQ

常见问题

这些问题通常决定一次训练是“可运行”，还是“结果可信”。

为什么只训练名称包含 cls 的参数？

这是当前任务的冻结策略：使用完整预训练主干，只更新分类相关模块。正式训练会要求所有非 cls 参数和 buffer 100% 加载，并可验证冻结参数训练前后逐位不变。

为什么 0.99 不能直接称为 99% 真实概率？

训练采样把类别调整为约 50/50，并加入阈值间隔损失，改变了自然先验。当前 0.99 被明确记录为业务分数；如需概率解释，应在自然分布 calibration 集上拟合 temperature 与 bias。

为什么周期 full test 叫 observed_dev_test？

因为它参与最佳模型选择，本质上承担 dev set 角色。若需要对外报告无偏指标，还应准备一个从未参与选模的独立 final test。

什么时候应该使用 packed 后端？

先在本地 NVMe 上做相同参数的 PNG/packed A/B。若 PNG 解码、CPU 或小文件随机读取限制了 NPU 利用率，再使用 packed；不要仅凭实现存在就假设它一定更快。

如何从中断位置继续训练？

将 train.resume_path 指向 checkpoint_last.pth。恢复会校验基础权重哈希和 trainable key 集，并恢复 optimizer、scheduler、scaler、sampler 位置及各 rank 随机状态。

Ready for hardware validation

先证明链路可靠，再让八张卡长时间工作

推荐顺序是：数据审计 → CPU smoke → 1P smoke → 8P smoke → checkpoint 恢复 → PNG/packed A/B → 正式训练。每一步都有明确产物和停止条件。
